# Автотесты онлайн-пополнения МТС

Java 17+, Maven 3.9+, Google Chrome. Selenium Manager автоматически подбирает драйвер Chrome; при первом запуске нужен доступ к интернету для его загрузки.

## Структура проекта

Все классы расположены в `src/test/java/ru/lesson`:

```text
base/
  BaseTest.java
  BasePage.java
pages/
  OnlinePaymentPage.java
  ServiceInfoPage.java
  PaymentWidgetPage.java
tests/
  OnlinePaymentTest.java
```

`BaseTest` управляет созданием и закрытием браузера, его настройками и сохранением материалов при падении теста. Тестовые классы наследуются от него; JUnit сначала выполняет подготовку браузера в базовом классе, затем подготовку страницы в тестовом классе.

`BasePage` содержит общие ожидания, чтение текста, клики, ввод и прокрутку. Классы в `pages` наследуют его и скрывают локаторы и работу с Selenium. Переходы возвращают объект открывшейся страницы: `clickMoreInfo()` — `ServiceInfoPage`, `clickContinue()` — `PaymentWidgetPage`.

`OnlinePaymentTest` содержит четыре сценария и проверки результатов. Поиск элементов, ожидания и управление браузером выполняются в классах страниц и базовых классах.

## Запуск

Из каталога `mts-tests`:

```powershell
mvn test
```

Или из корня репозитория:

```powershell
mvn -f mts-tests/pom.xml test
```

По умолчанию браузер работает без окна. Для запуска с видимым браузером:

```powershell
mvn test "-Dheadless=false"
```

## Проверки

1. Точное название блока «Онлайн пополнение без комиссии» с нормализацией переносов строк.
2. Наличие всех пяти логотипов: Visa, Verified By Visa, MasterCard, MasterCard Secure Code, Белкарт. Для каждого проверяются видимость и успешная загрузка изображения.
3. Нажатие «Подробнее о сервисе», переход на ожидаемый адрес и заголовок открывшейся страницы.
4. Выбор «Услуги связи» через выпадающий список, заполнение номера `297777777`, суммы `10` и email `test@example.com`, нажатие «Продолжить». Проверяются загрузка поля карты в iframe bePaid, сумма `10.00 BYN`, услуга и номер `375297777777` в описании платежа.

Тест останавливается на открытой платёжной форме: данные карты не вводятся, оплата не выполняется, чек не отправляется.

Каждый тест запускает отдельный браузер и не зависит от порядка выполнения. Действия выполняются обычными кликами и вводом; JavaScript используется для прокрутки и чтения состояния загрузки изображений. Используются явные ожидания без `Thread.sleep` и повторных попыток прохождения тестов.

Отчёты JUnit находятся в `target/surefire-reports`. При ошибке в теле теста снимок экрана и HTML сохраняются в `target/failure-artifacts/<имя класса теста>`. Тесты обращаются к действующему сайту и сервису bePaid, поэтому для выполнения требуется доступ к обоим сервисам.
